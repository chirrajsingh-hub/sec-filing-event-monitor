# SEC 8-K Event Monitor & Weekly Analyst Memo

Not a dashboard -- a repeatable research workflow. Every week, pull the
material 8-K filings from a 30-company sector, classify them by disclosed
event type, score them for materiality and urgency against a documented
rubric, and turn the result into a memo written the way an analyst covering
the sector would actually write it up: what happened, why it matters, what
to watch next, with a link back to the primary source for every claim.

**Live demo:** [secmonitorsite.vercel.app](https://secmonitorsite.vercel.app)
-- auto-updated weekly by [`.github/workflows/weekly-secmonitor-update.yml`](.github/workflows/weekly-secmonitor-update.yml),
which reruns the real pipeline against live EDGAR data every Monday and
redeploys. What you see there was generated by this code, not updated by
hand.

```
EDGAR (submissions API)  ->  classify by Item code  ->  score  ->  render memo
   (edgar_client.py)          (events.py)              (scoring.py)   (memo.py)
                                                                          |
                                                          pipeline.py orchestrates all of it
```

## Quick start

```bash
pip install -r requirements.txt && pip install -e .

# offline demo -- synthetic sample week, no network required
python examples/run_secmonitor.py

# real EDGAR data -- requires outbound network access to sec.gov/data.sec.gov
# and a contact email (SEC's fair-access policy requires an identifying
# User-Agent on every request: https://www.sec.gov/os/webmaster-faq#developers)
python examples/run_secmonitor.py --mode live --contact-email you@example.com

# add a real news layer on top of either mode -- get a free key at
# https://www.alphavantage.co/support/#api-key
export ALPHAVANTAGE_API_KEY=your_key_here
python examples/run_secmonitor.py --mode live --contact-email you@example.com
# (or pass --alpha-vantage-key your_key_here instead of the env var)
```

Output lands in `examples/output/`: a Markdown memo and a CSV of the
underlying scored events.

**Why offline is the default:** the pipeline needs a network-free path to
develop and test against, since not every environment (including some CI
runners and sandboxes) has outbound access to `sec.gov`.
`secmonitor/fixtures.py` is a hand-written, clearly-labeled synthetic week
(the rendered memo carries a "SAMPLE DATA" banner whenever it's used) that
exercises every stage of the pipeline with a known, diverse mix of event
types. `--mode live` runs the exact same classification, scoring, and memo
code against real EDGAR filings -- nothing about the pipeline changes, only
where the filings come from. This has been run and verified against real,
live EDGAR data.

## The data model

**Universe** (`universe.py`): 30 semiconductor and semiconductor-equipment
companies, ticker + name only. CIKs are resolved at run time from EDGAR's
`company_tickers.json` rather than hard-coded, since that mapping changes
occasionally (relistings, spinoffs).

**Classification** (`events.py`): SEC 8-Ks self-classify -- every filing
discloses which numbered "Items" it covers (`5.02` = officer/director
change, `4.02` = restatement, `1.05` = cybersecurity incident, etc.), and
the submissions API returns those codes directly. That means no NLP is
needed to know *what kind* of event a filing is, only *how material* --
see `ITEM_TAXONOMY` for the full 21-item mapping to a category label, a
one-line description, and a materiality/urgency baseline.

**Scoring** (`scoring.py`): materiality and urgency (1-10 each) start from
the item's baseline and are adjusted by a small, fully documented set of
keyword rules -- e.g. "material weakness" bumps a restatement filing,
"CEO"/"CFO" bumps a leadership-change filing more than a lower-officer
change would. Every score carries a plain-English rationale string in the
memo, on purpose: a number a reader can't trace back to a reason isn't
worth including.

**Memo** (`memo.py`): groups events by category, pulls out the highest
scores into a Highlights section, and closes with a Methodology appendix
restating the rubric and its limitations -- so the memo is legible on its
own, without needing to read the source code to know what a "materiality:
8/10" claim is actually based on.

**News** (`news_client.py`, optional): a second, independent real-data
layer via Alpha Vantage's `NEWS_SENTIMENT` endpoint -- real articles from
financial outlets, tagged per-ticker with a relevance score and a
sentiment label. It's deliberately *not* fused into the EDGAR events:
Alpha Vantage has no concept of an 8-K or an Item code, so it can't
classify or score a filing, and guessing which article corresponds to
which filing would be more noise than signal. Instead it renders as its
own "This week in sector news" section, clearly labeled as a separate
source, for the same coverage window. Supply a key (`--alpha-vantage-key`
or the `ALPHAVANTAGE_API_KEY` env var) and it runs alongside either
`--mode`; omit it and that section is skipped entirely. Free-tier keys are
rate- and quota-limited (historically 5 requests/minute, 25/day -- check
Alpha Vantage's site for current numbers), so the client batches the
whole tracked universe into a handful of multi-ticker calls rather than
one call per company, and a failed batch is recorded as a warning rather
than aborting the run.

**Site** (`site/`): the live demo is a static page whose data comes from
`site/data.js`, regenerated weekly by `scripts/generate_site_data.py`
(invoked by the GitHub Actions workflow) from a real pipeline run --
not hand-edited, not simulated in the browser.

## Honest limitations

- **Keyword scoring is blunt.** It has no notion of negation, dollar
  magnitude, or company-specific context -- "the company denies the
  lawsuit has merit" and "the company was found liable" both just contain
  "lawsuit." Treat every score as a triage signal for which filing to read
  first, not a verdict.
- **"Why it matters" / "Watch next" text is templated per event category,
  not a per-company financial analysis.** It's the analyst prompt a human
  (or a further research step) would start from -- it doesn't know a given
  company's balance sheet, valuation, or competitive position.
- **Live-mode snippets aren't implemented yet.** Real EDGAR filings score
  from the item-code baseline alone (no filing-text keyword boost) unless
  you extend `edgar_client`/`pipeline` to fetch and lightly clean the
  primary document text, the way `fixtures.py` hand-supplies it for the
  offline demo.
- **Item 8.01 ("Other Material Events") is a real catch-all**, used for
  everything from a routine press release to major litigation, under one
  base score. It deliberately scores conservatively for that reason --
  read the filing.
- **This is not investment advice, and the offline demo is not real
  data.** Company tickers/names in the fixtures are real; the events
  attributed to them are invented for demonstration and are clearly
  labeled as such in the rendered memo.
- **The news section isn't matched to specific filings.** It's real
  articles for the same tickers and coverage window, shown alongside the
  EDGAR events as context -- not a claim that a given article explains a
  given filing. Alpha Vantage's sentiment labels are its own model's
  output, not this project's scoring.

## Repository layout

```
secmonitor/
  universe.py       Sector + company list (ticker, name)
  edgar_client.py    Live EDGAR client: CIK resolution, 8-K fetch, URL building
  news_client.py     Optional live Alpha Vantage news client (NEWS_SENTIMENT)
  fixtures.py        Offline synthetic sample week (network-free demo/tests)
  events.py          8-K Item-code taxonomy and classification
  scoring.py         Materiality/urgency rubric with keyword rules
  memo.py            Markdown memo renderer + per-category commentary
  pipeline.py        Orchestration: fetch -> classify -> score -> render
  cli.py             `python -m secmonitor.cli` entry point
examples/
  run_secmonitor.py
scripts/
  generate_site_data.py   Regenerates site/data.js from a live pipeline run
site/
  index.html, data.js     The live demo (static page, data-driven)
.github/workflows/
  weekly-secmonitor-update.yml   Weekly cron: rerun pipeline, commit, redeploy
tests/
  test_events.py, test_scoring.py, test_edgar_client.py,
  test_news_client.py, test_memo.py, test_pipeline.py
```
