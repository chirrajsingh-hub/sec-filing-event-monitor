Event-driven research workflow

Raw SEC filings, turned into a weekly analyst memo.

Every week, an automated job pulls the material 8-K filings from 30 semiconductor companies straight from SEC EDGAR, classifies each one by disclosed event type, scores it for materiality and urgency against a documented rubric, and writes the result up the way an analyst covering the sector would — sourced back to the original filing. Not a dashboard. A repeatable, self-updating process.

How it works

Four stages, each its own module, each independently tested — plus a scheduled job that reruns the whole thing weekly.

01

Fetch

Pull every recent 8-K for the tracked universe directly from SEC EDGAR's public submissions API — no scraping, the SEC's own structured data. edgar_client.py

02

Classify

Every 8-K discloses which numbered "Item" it covers — 5.02 is a leadership change, 4.02 is a restatement, 1.05 is a cybersecurity incident. That mapping is built directly into the filing, so classification needs no guessing. events.py

03

Score

Each event category has a documented materiality/urgency baseline (1–10), adjusted by a small, transparent set of keyword rules. Every score carries a written rationale — nothing is a black box. scoring.py

04

Write & republish

Assembles everything into this page. A GitHub Actions job reruns steps 1–4 every week against live EDGAR data and redeploys automatically — what you're reading was generated by code, not updated by hand. .github/workflows/weekly-secmonitor-update.yml

Methodology & honest limitations

Classification. Each 8-K's disclosed Item codes map directly to an event category — a filing with multiple items is headlined by its most material substantive item.

Scoring. Materiality and urgency start from a per-category baseline, adjusted by documented keyword rules (e.g. "material weakness" on a restatement, "CEO"/"CFO" on a leadership change). Every score ships with its rationale.

What this run doesn't do yet. Live filings are scored from the item-code baseline alone — the pipeline doesn't fetch and read filing text yet, so nothing here is keyword-boosted. The "why it matters" / "watch next" text is templated per category, not bespoke analysis of each company. Item 8.01 is a catch-all spanning routine press releases to major litigation, scored conservatively for that reason. Every score is a triage signal, not a verdict — read the linked filing.

Stack

Pure Python, no framework, no database — a pipeline, not a service. Kept fresh by a weekly scheduled job, not a person.
